# Plan 2: API de cuentas y diseños

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** API REST .NET 10 hexagonal con PostgreSQL: registro en dos pasos por correo (y el diseño anónimo que viaja con la solicitud), sesiones con JWT revocable, contraseñas, baja de la cuenta y CRUD de diseños con control de concurrencia.

**Architecture:** Igual que `C:\Desarrollo\Proyectos\jornal` (léase su `CLAUDE.md` y `spec/constitution/tech-stack.md`): `Decorazon.Dominio` → `Decorazon.Aplicacion` → `Decorazon.Infraestructura` / `Decorazon.Api`, más `Decorazon.Contratos`. Las dependencias apuntan hacia dentro y lo vigilan tests de arquitectura. **Casi todo lo de cuentas se porta de jornal**: se copia el fichero, se cambia `Jornal` → `Decorazon` y se quita lo que es solo de jornal (trabajadores, clientes, trabajos, cobros, accesos, invitaciones, resumen, exportación). Lo que se porta llega con sus tests.

**Tech Stack:** .NET 10 (SDK 10.0.301), ASP.NET Core con endpoints mínimos, EF Core 10 + Npgsql + EFCore.NamingConventions, JWT Bearer, xUnit, Testcontainers (Docker), las mismas versiones de paquetes que jornal.

**Spec:** `docs/superpowers/specs/2026-10-24-decorazon-design.md` (§5, §6.1, §7, §8).

## Global Constraints

- Nombres en español; namespaces de archivo; sin avisos de compilación (`TreatWarningsAsErrors` como jornal); `.editorconfig` copiado de jornal.
- Tablas y columnas en `snake_case`; Ids `Guid` generados por el dominio con `ValueGeneratedNever()`.
- Contraseñas PBKDF2 con sal, **12–128** caracteres; tokens de correo de 256 bits guardados como SHA-256, un solo uso, con caducidad: **registro 24 h**, **contraseña 1 h**.
- Las respuestas no revelan si un correo tiene cuenta. Tablas separadas para solicitudes de registro y de contraseña.
- JWT revocable por versión de credenciales (`ver_cred`), comprobada en cada petición. Cambiar o restablecer la contraseña sube la versión.
- La identidad sale del JWT, nunca del cuerpo. **Un diseño ajeno o inexistente responde `404`.**
- Diseños: máximo **100 por usuario**; contenido ≤ **1 048 576 bytes** (UTF-8); nombre de **1 a 100** caracteres (recortado); `tipoEstancia` ∈ `dormitorio | salon | cocina`.
- Contenido del diseño: JSON guardado en columna `jsonb`. La API **no interpreta la geometría**: solo comprueba que es un objeto JSON con `formato` entero admitido (hoy solo `1`), `estancia` objeto y `aberturas`, `estructura`, `elementos` arrays; y el tamaño.
- Concurrencia: cada diseño tiene `Version` (empieza en 1, +1 en cada cambio). `ETag: "<version>"`. `PUT` exige `If-Match`: sin él `428`, distinto `412`.
- Anti-abuso del registro: como mucho **3 solicitudes por correo cada hora** (en el caso de uso) y **10 por IP cada hora** (limitador). Una solicitud nueva para el mismo correo invalida la anterior y su diseño. Si el correo ya tiene cuenta, el diseño no se guarda.
- Puertos locales: API **5320**, PostgreSQL **5435**, web (Vite, plan 3) **5321**. CORS: `https://decorazon.angelgf.com.es` en producción y `http://localhost:5321` en desarrollo.
- Secretos (cadena de conexión, clave JWT, clave de Brevo) fuera del repositorio: `appsettings.Development.json` ignorado; en el repo solo `appsettings.Example.json`. En desarrollo y tests el correo va al log con `[CORREO SIMULADO]`.

## Review Focus

1. Completar el registro con un token de **otra** solicitud del mismo correo (la invalidada por una petición posterior) → `EnlaceNoValido` y ningún diseño de la solicitud vieja llega a la cuenta → test en Task 4.
2. `PUT` concurrente: dos clientes leen la versión 3, ambos guardan; el segundo recibe `412` y el diseño conserva el contenido del primero → test en Task 8.
3. Contenido JSON hostil: `null`, un array, un número, JSON roto, 1 048 577 bytes, `formato: 2`, `formato: "1"` → `400` con mensaje claro, nunca `500` → tests en Task 2 y Task 8.
4. Usuario A pide `GET/PUT/DELETE/duplicar` sobre un diseño de B → `404`, y el diseño de B queda intacto → test en Task 8.
5. Borrar la cuenta borra también todos sus diseños, y el JWT anterior deja de valer → test en Task 8.

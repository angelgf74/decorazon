# Plan 6: despliegue completo con srv

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Este plan mezcla cambios de código (Task 1) con pasos en el servidor que solo puede hacer Angel (sudo y secretos) y que siguen la skill `servidor`: nada cambia en el servidor sin un ensayo previo y sin el sí de Angel a ese comando concreto.

**Goal:** Publicar en agfserver la API con su base de datos en `decorazon-api.angelgf.com.es` y la web nueva (plan 5) en `decorazon.angelgf.com.es`, y comprobar en producción el recorrido completo con correo real.

**Architecture:** Un único `srv.json` con la web estática (ya publicada en el plan anterior a este), la API .NET, las migraciones (bundle de EF) y la base `decorazon`. Los secretos los pone Angel con `srv secreto`, y el resto de la configuración de producción ya está en `appsettings.json`.

**Tech Stack:** srv 0.2 (skill `servidor`), .NET 10, PostgreSQL del servidor, nginx tras el túnel de Cloudflare y Brevo.

**Spec:** `docs/superpowers/specs/2026-10-24-decorazon-design.md` (§3 despliegue, §5 correo, §7 CORS y secretos, §9 `no-transform`). Pendientes que recoge: "Para el plan 6" de `2026-10-25-02-pendientes.md` y de `2026-10-30-05-pendientes.md`.

## Global Constraints

- **Skill `servidor`, reglas 1 a 7:**
  - primero el ensayo y después `--publicar`, con el sí de Angel para cada comando;
  - `srv configurar --publicar` y `srv secreto` los ejecuta Angel en su propia terminal;
  - nunca se leen ni se muestran secretos (`srv secreto --nombres` para ver solo los nombres);
  - nunca se borra nada del servidor a mano.
- **Ningún secreto en el repositorio ni en el chat.** Angel genera la clave JWT (`openssl rand -base64 48`) y la pega directamente en `srv secreto`.
- **Secretos:** `ConnectionStrings__Decorazon`, `Jwt__ClaveDeFirma` (al menos 32 caracteres) y `Correo__ClaveDeApi`. El resto ya está en `appsettings.json`: `Correo:UsarBrevo true`, remitente `no-responder@angelgf.com.es`, `BaseDeLaWeb https://decorazon.angelgf.com.es` y CORS `https://decorazon.angelgf.com.es`.
- **`tamanoMaximo: "2m"`** en la API: un diseño de 1 MB más su envoltorio supera el 1 MiB de nginx por defecto.
- **Cuentas de prueba:** Claude no crea cuentas ni escribe contraseñas en producción. El registro de prueba lo hace Angel, y Claude solo guía y comprueba.

## Review Focus

1. Que la API arranque en producción con solo los tres secretos: la validación de arranque es estricta (Brevo, https, Jwt). → Task 3: `srv subir` espera a `/salud`.
2. CORS: que el navegador desde `https://decorazon.angelgf.com.es` pueda llamar a la API, incluidas las cabeceras `Authorization`, `If-Match` y la expuesta `ETag`. → Task 3: preflight con `curl`.
3. Que el correo llegue de verdad, con enlaces https a la web, y que el remitente esté verificado en Brevo. → Task 4.
4. Que el límite de peticiones por IP vea la IP real del cliente (nginx sobrescribe `X-Forwarded-For` y la API confía solo en el loopback), no la del túnel. → Task 4: tras 11 registros seguidos desde un mismo origen sale 429, pero no afecta a otros.
5. Que una pestaña abierta con la versión anterior no se rompa al pulsar "3D" tras el despliegue (fragmento con hash viejo). → Task 1.

### Task 3: Publicar y verificar

- [ ] **Step 1:** Con el sí de Angel, `srv subir --publicar`. srv:
  - sube el paquete y migra la base con el bundle;
  - cambia `current`;
  - arranca la API y espera a `/salud`;

  Si algo falla, srv vuelve sola a la release anterior. Enseñar `srv logs api` y no proponer `srv volver` sin el sí de Angel.
- [ ] **Step 2:** Comprobaciones, todas por el dominio público:
  - `curl -s https://decorazon-api.angelgf.com.es/salud` responde `{"estado":"correcto","baseDeDatos":true}`.
  - El preflight `curl -si -X OPTIONS https://decorazon-api.angelgf.com.es/disenos -H "Origin: https://decorazon.angelgf.com.es" -H "Access-Control-Request-Method: PUT" -H "Access-Control-Request-Headers: authorization,if-match,content-type"` da 204, con `Access-Control-Allow-Origin` igual al origen y las cabeceras permitidas.
  - Con un origen ajeno (`https://ejemplo.com`), la respuesta no lleva `Access-Control-Allow-Origin`.
  - `curl -sI https://decorazon.angelgf.com.es/sw.js` y `/manifest.webmanifest` llevan `Cache-Control: no-cache, no-transform`.
  - `srv estado` muestra la release activa y la API "activa" y sana.

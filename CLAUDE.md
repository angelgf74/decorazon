# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Qué es

**Decorazon**: editor web de diseños. Cada usuario crea, guarda y edita sus diseños (hasta 100 por usuario, 1 MB cada uno). Especificación en `docs/superpowers/specs/2026-10-24-decorazon-design.md`; planes y pendientes en `docs/superpowers/plans/`.

## Estructura

```
web/                     editor en TypeScript: web/src/editor es la interfaz (React) y web/src/nucleo/edicion son las operaciones puras; el núcleo (geometría y reglas) vive en web/src/nucleo
src/Decorazon.Dominio    núcleo de la API: entidades, invariantes, puertos. Sin dependencias.
src/Decorazon.Aplicacion casos de uso. → Dominio
src/Decorazon.Infraestructura  EF Core + PostgreSQL, adaptadores. → Dominio
src/Decorazon.Contratos  DTOs públicos. → nadie
src/Decorazon.Api        endpoints mínimos y composición. → Aplicacion, Contratos, Infraestructura
tests/                   un proyecto de tests por capa; Arquitectura.Tests vigila las flechas
```

**Regla de dependencias:** las flechas de arriba son las únicas permitidas; los tests de `Decorazon.Arquitectura.Tests` las hacen cumplir (ensamblados y `.csproj`). Si fallan, se corrige la dependencia, no el test.

## Comandos

```bash
# PostgreSQL local (puerto 5435 del host)
docker compose up -d

# Configuración local (una vez)
cp src/Decorazon.Api/appsettings.Example.json src/Decorazon.Api/appsettings.Development.json

# API en http://localhost:5320 (migra sola en Development)
dotnet run --project src/Decorazon.Api

# Web en http://localhost:5321
cd web && npm run dev -- --port 5321

dotnet build Decorazon.slnx -warnaserror
dotnet test Decorazon.slnx                                  # necesita Docker (Testcontainers)
dotnet test Decorazon.slnx --filter "Categoria!=Integracion" # sin Docker
cd web && npm test                                          # tests del núcleo TS
cd web && npm run e2e                                      # recorrido de extremo a extremo con Playwright (compila y sirve en el 5322)
                                                            # incluye e2e/vista3d.spec.ts: el 3D con SwiftShader (sin GPU), canvas con contenido y sin errores de consola
cd web && npm run e2e:cuentas                              # cuentas y diseños con la API real (5320) y PostgreSQL: necesita docker compose up -d
                                                            # base decorazon_e2e, clave JWT aleatoria y correos en web/test-results/correos
cd web && npm run api:tipos                                # regenera src/api/esquema.d.ts desde src/api/openapi.json
cd web && npm run miniaturas                               # regenera las miniaturas 3D del catálogo (public/miniaturas y su manifiesto), ~40 s
                                                            # hoja de contacto con todas en web/test-results/miniaturas.png
```

`npm run e2e:cuentas` arranca su propia API y su preview: los puertos 5320 y 5322 tienen que estar libres.

## Web ↔ API

- El cliente (`openapi-fetch`) y los tipos (`web/src/api/esquema.d.ts`) salen de `web/src/api/openapi.json`, que escribe el build de la API. Los dos van en git y el CI comprueba que están al día: tras cambiar un contrato, `dotnet build` y `npm run api:tipos`.
- `web/package.json` lleva un `overrides` para que `openapi-typescript` use el TypeScript 6 del proyecto (su peer pide ^5). Se quita cuando `openapi-typescript` soporte TS 6.
- `PUT /disenos/{id}` reemplaza el diseño entero: siempre con `nombre`, `tipoEstancia` y `contenido`, más `If-Match`.
- Claves de `localStorage`:
  - `decorazon.sesion`: token, caducidad y correo del usuario;
  - `decorazon.disenoAnonimo`: el diseño sin cuenta;
  - `decorazon.diseno.<id>`: copia local de cada diseño del servidor, con su versión y si tiene cambios sin subir;
  - `decorazon.catalogo.favoritos` y `decorazon.catalogo.recientes`: ids de tipos del catálogo (favoritos; últimos 6 añadidos);
  - `decorazon.tienda.productos`: mis productos de tienda (M-17), hasta 30, el último usado primero; lo que no valida al leer se descarta (`editor/paneles/misProductos.ts`). No tiene datos personales: `cerrarSesion()` no lo borra;
  - `decorazon.registroEnviado`: el diseño que viajó con el registro; al entrar no se pregunta si guardarlo solo si la cuenta tiene un diseño con ese mismo contenido (se comprueba en el servidor; ante la duda, se pregunta).
- `cerrarSesion()` (salida voluntaria o borrado de la cuenta) borra las copias `decorazon.diseno.*`, el diseño anónimo y `decorazon.registroEnviado`, y el editor anónimo empieza vacío; "Cerrar sesión" con cambios sin subir pide confirmación antes. `cerrarSesion('caducada')` conserva las copias para subir lo pendiente al volver, y `cerrarSesion({ conservarLocales: true })` (tras cambiar la contraseña, mismo usuario) también. Si otra pestaña cierra la sesión o entra con otra cuenta (evento `storage` sobre `decorazon.sesion`), esta pestaña la olvida, vuelve al anónimo y va al inicio sin borrar nada del almacenamiento; si entra con la misma cuenta, adopta el token nuevo y sigue donde estaba. `iniciarSesion()` no toca `decorazon.sesion` hasta tener la sesión nueva.

Los tests de integración llevan `[Trait("Categoria","Integracion")]`; de ahí el filtro.

## Secretos y configuración

- `appsettings.Development.json` está ignorado por git; `appsettings.Example.json` es la plantilla.
- Los secretos de producción van por variables de entorno, con `srv secreto` (skill `servidor`): `ConnectionStrings__Decorazon`, `Jwt__ClaveDeFirma` y `Correo__ClaveDeApi`.
- Los valores de producción que no son secretos viven en `appsettings.json`: el origen CORS y el correo (`Correo:UsarBrevo: true`, remitente y `Correo:BaseDeLaWeb` https).
- El correo depende de `Correo:UsarBrevo`. Con `false` (desarrollo y tests) no se envía: el enlace va al log con `[CORREO SIMULADO]`. Fuera de Development y Testing la API no arranca sin Brevo (salvo `Correo:Simulado: true`) ni con una `Correo:BaseDeLaWeb` que no sea https.
- Administración: `Administracion:Correos` (lista; vacía en `appsettings.json`, en producción `Administracion__Correos__0`) dice qué cuentas administran. No es un secreto ni una cuenta especial: la persona se registra como cualquiera.
- Las sugerencias (`POST /sugerencias`) se entregan al buzón del proyecto GestorSugerencias (`Sugerencias:UrlBase`, sin clave; `appsettings.json` lo trae activo). En Development y Testing `Program` fuerza `Sugerencias:UsarServicioReal=false` pase lo que pase en la configuración: van al log con `[SUGERENCIA SIMULADA]`. Fuera, la API no arranca sin el buzón (salvo `Sugerencias:Simulado: true`) ni con una `UrlBase` que no sea https.

## Reglas globales

- Máximo 100 diseños por usuario y 1 MB por diseño.
- Concurrencia con `ETag` / `If-Match`.
- Diseño ajeno o inexistente: `404`.
- La identidad sale solo del JWT, nunca del cuerpo.

## Lecciones que no son obvias

- `jsonb` rechaza `\u0000` y los escapes de sustituto suelto, así que `ContenidoDeDiseno.Validar` los rechaza.
- Los objetos de valor de nombre y correo rechazan caracteres de control: PostgreSQL no admite NUL en `text`.
- `jsonb` reformatea el JSON guardado: al rehidratar se usa `ContenidoDeDiseno.Reconstruir` y nunca se revalida.
- `IRepositorioDeDisenos.Anadir` solo hace seguimiento; `IRepositorioDeUsuarios.AnadirAsync` guarda el `DbContext` compartido.
- Cambiar la contraseña invalida el token de quien la cambia.
- El contenido rechaza números con exponente o de más de 32 caracteres: jsonb los guarda como `numeric` exacto y `1e200000` reventaba al guardar.
- El diseño anónimo vive en `localStorage` bajo `decorazon.disenoAnonimo`, y todo número se redondea a 2 decimales al guardar para que `JSON.stringify` nunca emita exponentes.
- Los adaptadores traducen la concurrencia de EF y los errores 23505/23503 de PostgreSQL a resultados del puerto (`false`); la aplicación nunca ve tipos de EF ni de Npgsql. La fecha de consumo de las solicitudes es token de concurrencia: un enlace solo se usa una vez aunque lleguen dos peticiones a la vez.
- Sugerencias: `POST /sugerencias` no pide sesión. Con un token válido se responde al correo de la cuenta y el `correo` del cuerpo se ignora; sin token, ese correo es obligatorio. Un `Authorization` que no valida da 401, no "sin sesión": así la web cierra la sesión en vez de pedir un correo. Decorazon no guarda la sugerencia: si el buzón falla, 502 y la web conserva lo escrito. El buzón admite correos de 200 caracteres (una cuenta, 254): más largos, 400 antes de mandarlos. El tipo viaja al buzón por nombre (`NuevaFuncionalidad`…), no por número: el buzón no valida el rango de su enumerado y un número cambiaría de sentido si lo reordenan. Límite propio: 5 por hora, por cuenta o por IP.
- La barra del editor tiene tres zonas (diseño y guardado, pasos, deshacer/menú/cuenta). "Nuevo diseño", "Imprimir" y "Sugerencias" están en el menú "Más acciones" (`MenuMas` en `BarraSuperior.tsx`): solo existen en el DOM con el menú abierto, y al elegir una opción el foco vuelve al botón del menú **antes** de ejecutarla (la hoja para imprimir guarda `document.activeElement` para devolverle el foco al cerrarse). En móvil el botón de sugerencias va en las pestañas de abajo (`PestanasDeHojas`), al alcance del pulgar, y la opción del menú se oculta por CSS. 2D/3D no va en la barra sino sobre el plano (`SelectorDeVista` en `Editor.tsx`, dentro de `.editor__lienzo`, porque el `Lienzo` se desmonta en 3D); zoom y Encuadrar abajo a la derecha (`.lienzo__controles`, y la barra de la vista 3D en el mismo sitio); las pistas son una píldora abajo a la izquierda que en móvil enseña solo las dos primeras. El panel derecho solo existe en escritorio cuando hay una selección del paso (`seleccionDelPaso` en `almacen.ts`; clases `editor__cuerpo--sin-panel` y `editor__derecha--oculta`); los avisos de conflicto son un chip arriba a la izquierda del plano (`AvisosDelPlano`, en 2D y 3D) que despliega la lista, y los atajos de teclado van en un `<details>` al pie del panel. Las flechas mueven lo seleccionado 1 cm (10 con Mayúsculas) **sin imán** (`desplazarElemento` en `nucleo/edicion/elementos.ts`; `moverElemento` siempre imanta y desharía el ajuste fino) y las pulsaciones seguidas son un solo paso de deshacer (grupo `teclado:…`, cerrado al soltar la tecla); se ignoran con `e.defaultPrevented`, porque el menú ya usa ↑↓. El chip de avisos no lleva `role="status"` (en reposo el único `status` del editor es el guardado de la barra, y así lo cuentan los tests de `EditorDeDiseno`): el lector de pantalla recibe el número de avisos por una región `aria-live` oculta que va siempre en el mismo sitio del árbol, con 600 ms de retardo para que un arrastre solo anuncie el final y sin repetir el mismo número. El catálogo es una rejilla de dos columnas con chips de grupo (un chip pulsado deja solo ese grupo; el buscador filtra dentro de lo que se enseña), y el panel de Estancia termina con el botón "Amueblar" que pasa al paso 2. Cada tarjeta lleva la miniatura 3D del tipo (`MiniaturaDeTipo`; ver «Miniaturas 3D del catálogo» más abajo) y, si no tiene o no carga, su huella, dibujada con la misma `Pieza` (`lienzo/capas/Pieza.tsx`) que pinta el plano. Delante van «Favoritos» (estrella, un botón hermano de la tarjeta dentro del `<li>`: un botón dentro de otro no es válido) y «Usados hace poco» (los apunta `anadirTipo`), solo si tienen algo; viven en `localStorage` (`decorazon.catalogo.favoritos` y `decorazon.catalogo.recientes`) por `paneles/catalogoLocal.ts`, que guarda en memoria lo que `localStorage` rechaza y avisa a React con `useSyncExternalStore`.
- Vista de administración: `EmisorDeAccesoJwt` pone el claim `admin` (`ClaimsPropios.Administrador`) a los correos de `Administracion:Correos` (sin mayúsculas, por `OpcionesDeAdministracion`); se decide al emitir, así que quitar un correo surte efecto en su siguiente inicio de sesión (o al caducar el token, 7 días). La política `Politicas.Administrador` protege `GET /administracion/usuarios`: sin el claim, **403** y no 404 (la ruta está en el OpenAPI y en la web; un 401 cerraría la sesión). Devuelve cada cuenta con su número de diseños y los bytes que ocupan en PostgreSQL (`pg_column_size` de `disenos.contenido`, `vistas_previas.imagen` y `versiones_anteriores.contenido`: tamaño almacenado, comprimido por TOAST, no el del JSON), de más a menos espacio, con totales. La consulta es SQL literal en `ConsultaDeUsuariosEf` (`SqlQuery`, sin parámetros), con columnas en snake_case porque la convención del contexto también se aplica al tipo de la fila. `GET /cuentas/yo` trae `esAdministrador` (del claim) y la web lo usa solo para enseñar el enlace «Administración» en Mi cuenta y Mis diseños; la página (`/administracion`, `web/src/administracion/`) no es indexable, lleva al inicio a quien no administra o recibe 403, y la tabla se desplaza dentro de su caja en móvil.
- xUnit serializa los datos de `InlineData`: un sustituto suelto llega al test como U+FFFD. Esas cadenas se arman dentro del test.
- jsdom trata un `<footer>` dentro de `<main>` como `contentinfo` y Chromium no: en los e2e, el pie del inicio se busca por su clase.
- «Descargar plano» (`editor/hoja/exportarPlano.tsx`) pinta el svg de `PlanoDelDiseno` con `renderToStaticMarkup` y le incrusta `ESTILOS_DEL_PLANO`, una copia a mano de las reglas de `lienzo.css` que el plano necesita con los colores de `base.css` resueltos (una imagen svg no ve las hojas de estilo): **al cambiar `lienzo.css` hay que revisarlo**. Sin canvas (jsdom) devuelve el svg. «Descargar imagen 3D» y la hoja para imprimir capturan con `CapturaFueraDePantalla` (1200 × 800 a dpr 2, un PNG de 2400 × 1600). El tope va en dos fases: 20 s hasta el primer fotograma (`alPrimerFotograma` de `Disparar`: fragmento, shaders y horneado, que sin GPU y con la CPU ocupada pasaban de 8 s y la hoja decía «no disponible») y 8 s desde él. `Captura3D` monta `Escena3D` con `sombras="suaves"`: `SombrasSuaves` (`AccumulativeShadows` + `RandomizedLight` de drei, 24 pasos horneados antes del primer fotograma, `memo` por valor porque drei rehornea en cada render) acumula sombras con penumbra sobre un receptor con la forma de la **planta** (`geometriaReceptor`, uv de 0 a 1; el plano cuadrado de drei dejaba caer sombras fuera de la estancia sobre el fondo transparente) y el suelo deja de recibir la sombra dura del sol. El receptor va con `frustumCulled = false`: el horneado desenvuelve por uv e ignora la posición, pero three lo descartaba por su caja envolvente y el suelo salía negro. `Disparar` sube el dpr solo dos fotogramas antes de capturar (los caros, en SwiftShader). La vista interactiva sigue con sombras duras y dpr [1, 2]; la vista previa, a dpr 1 y con `sombras="duras"` (es una miniatura, y el horneado hacía fallar `e2e/cuentas` en el CI al rozar los 10 s de `ESPERA_MS`). «Descargar diseño» produce `<nombre>.decorazon.json` con `serializarDocumento` (el mismo JSON que viaja al servidor); «Abrir un fichero» (inicio) e «Importar» (Mis diseños) lo leen con `importarDiseno` (`editor/persistencia/fichero.ts`: tope de 2 MB, `JSON.parse` y `validarDocumento`). `HojaImpresion` acepta `doc` y `nombre` por props (la vista compartida) y sin ellos lee el editor.
- `Elemento` lleva dos campos opcionales: `bloqueado?: true` (solo se guarda si es verdadero; `bloquearElemento` lo quita al liberar) y `nombre?: string` (hasta `LIMITE_NOMBRE_ELEMENTO` = 60, sin espacios a los lados; `renombrarElemento` lo quita si queda vacío). Un bloqueado se selecciona y se edita, pero `moverElemento` y `desplazarElemento` devuelven el mismo documento (así arrastre, tirador, flechas y R no apuntan un paso de deshacer vacío: `cambiar` ignora el mismo documento), `editarElemento` ignora su `rotacion` y ni `editar` ni `cambiarTipo` lo imantan (el imán también lo movería al cambiar medidas o producto), `pulsarElemento` no abre el arrastre y `CapaElementos` deja pasar el toque (`data-bloqueado`: arrastrar desde él hace pan y el toque sin mover no suelta la selección), el `Lienzo` no monta el `TiradorGiro` y `CapaElementos` dibuja un candado (`data-candado`, a tamaño fijo con `scale(1/escala)`, también en el plano exportado: `ESTILOS_DEL_PLANO`). `duplicarElemento` copia el nombre y la copia nace libre. `nombreDeElemento` prefiere el nombre propio al producto y al tipo: plano, panel, hoja y vista compartida lo heredan; `filasDeMuebles` añade `tipo` para escribirlo debajo. «Voltear» (`voltearElemento`) cambia izquierda ↔ derecha en toda variante que admita los dos valores (`sePuedeVoltear`); en una puerta cambia la bisagra.
- La cinta métrica es estado local del `Lienzo` (`midiendo`, `medida`): midiendo, ninguna capa lleva `alPulsar` ni hay tiradores (el toque cae al fondo) y un toque sin arrastre fija un punto en cm enteros; entre el primero y el segundo la cota sigue al puntero si no hay botón pulsado. Escape (oyente propio en `window`), el botón o cambiar de paso la quitan; no se guarda. `CotasElemento` pasa a `cotasAParedes` las huellas de los vecinos no pisables (`obstaculos`): la cota va a lo primero que corte el rayo.
- La vista previa (JPEG de 1200 × 630 que hace el navegador del dueño con `GeneradorDeVistaPrevia`) se rehace al guardar **cualquier** diseño de la cuenta (`RefrescoDeVistaPrevia`, como mucho una cada 5 minutos por diseño, `frecuencia.ts`), no solo los compartidos: es la miniatura de Mis diseños. `GET /disenos/{id}/vista-previa` la sirve al dueño (`private, no-store`: la dirección no cambia al rehacer la imagen y la web pide por id, así que una caché HTTP devolvería la vieja; ajeno o sin imagen, 404) y el resumen del listado trae `fechaDeVistaPrevia` (null sin imagen; el repositorio EF la proyecta con una subconsulta, sin leer la imagen). `MiniaturaDeDiseno` la pide con `parseAs: 'blob'` y guarda el object URL por `id:fecha` en `paginas/miniaturas.ts` para que buscar u ordenar no la vuelva a pedir (un fallo no se guarda). La espera de 5 minutos es «en cabeza»: el primer guardado hace la imagen al momento y los siguientes esperan; si se sale del editor con uno esperando, `RefrescoDeVistaPrevia` lo encola (`colaDeVistasPrevias.ts`) y `AnfitrionDeVistasPrevias`, montado en `App` fuera de las rutas, hace esa última imagen con lo último guardado. La marca de la espera es `decorazon.vistaPrevia.<id>` en `localStorage` (una fecha; no se borra). «Buscar» y «Ordenar por» de Mis diseños van en el cliente (`ordenarYFiltrar`; sin tildes ni mayúsculas con `normalize('NFD')`).
- «Nueva estancia» crea un rectángulo o una L: `documentoNuevo(tipo, ancho, largo, alto, forma?)` con `plantaDeForma` (`nucleo/modelo/crear.ts`; el entrante se recorta a `[50, medida − 50]` y las cuatro esquinas giran en el mismo sentido que el rectángulo). `almacen.crear` y `alCrear` de `NuevaEstancia` llevan la forma como quinto parámetro.
- Analítica: `iniciarAnalitica` (`analitica.ts`) carga el tracker de WebAnalytics con `?site=` y `evento(nombre, datos?)` cuenta lo que se usa llamando a `window.webanalytics.evento` (lo define el tracker): hasta 20 eventos se encolan mientras el script carga y salen en su `load`; si el script falla (adblocker) o no hay sitio, no se hace nada. Eventos: `estancia-creada` (`tipo`, `forma`) en `almacen.crear`, `mueble-anadido` (`tipo`) en `anadirTipo`, `vista-3d` en `cambiarVista` (solo al entrar), `hoja-impresa` (botón de `HojaImpresion`), `enlace-creado` (`DialogoCompartir`), `ejemplo-abierto` (`ejemplo`: nombre, en `Inicio`) y `catalogo-sin-resultados` (`texto`: lo buscado sin tildes ni mayúsculas, recortado a 30; `useBusquedaSinResultados` en `paneles/usarBusquedaSinResultados.ts`: al dejar de escribir 1,5 s, con 3 letras o más, solo si no existe en **todo** el catálogo, una vez por texto, y nunca con @ o cuatro cifras seguidas). Es el dato para elegir los tipos que faltan (M-16). **Nunca** datos personales ni ids de diseño; la política de privacidad (`textos.privacidad.anonimo`) lo dice. Nombres en minúsculas con guiones (la API de WebAnalytics rechaza otra cosa). Los tests que montan algo que emite eventos hacen `vi.mock` de `analitica`.
- Luces interiores (M-13): `lucesInteriores(doc)` en `nucleo/modelo3d/luces.ts` (función pura, con test) da una luz cálida por `lampara-pie` y una de día por ventana, con tope (`MAXIMO_LAMPARAS` 4, `MAXIMO_VENTANAS` 3: cada luz cuesta fps); `Escena3D` las pinta como `pointLight` con `castShadow={false}`. Salen en todo lo que monta `Escena3D`: el editor, la vista compartida (`Vista3DSoloVer`) y las capturas (`Captura3D`: imagen 3D, hoja para imprimir, vista previa). Las intensidades son las de three con luces físicas (decay 2): se notan sin quemar; si se cambian, mirar el salón de ejemplo en 3D.
- Variantes (plan 28): `DefinicionVariante` admite `etiquetas` por valor («Canapé», «Cama nido»; sin ella, el valor con mayúscula) y `ocultarConUnValor` para las dependientes: si `valoresPara` deja un solo valor, ni el panel ni la hoja la enseñan (el `lado` de una cama con patas). Sin la marca se enseña igual, a propósito: el lavabo estrecho sigue diciendo «Senos: 1». La cama tiene `base` (`patas`, `canape`, `cajones`, `nido`; solo `patas` con menos de 40 de alto) y `lado` (`izquierda`, `derecha`, `ambos` según la base); los `volumenes` no cambian y lo que sale va en `zonasApertura` con `zonaCaja` (la tapa del canapé hacia arriba sobre la mitad de los pies, cajones de 50 por el lado largo, la cama nido el ancho menos 10 por un lado): contra una pared da error y «Voltear» cambia el lado. El escritorio tiene `cajonera` (`no`, `izquierda`, `derecha`, `ambas`; sin `ambas` con menos de 100 de ancho): `tableroConApoyos` (volúmenes: cajonera de 40 del suelo al tablero o dos patas por lado), `cajoneraLateral` + `cajonesApiladosEn` (3D, frentes en un tramo de x) y `cajonesEn` (una zona «el cajón» por cajonera). `cajonesApilados` y `cajones` son los casos a todo el ancho. El escritorio en L tiene `cajonera` (Sí/No) en el extremo libre del tablero principal, el opuesto al ala («Voltear» la lleva con el ala): las ayudas aceptan `yFrente` (y `cajoneraLateral`, `yTrasera`) porque ahí el frente es el del tablero principal, no el del elemento.
- Material por zona y forma de las patas (plan 28c): `ZonaColor.materiales` lista los materiales que el usuario puede elegir para esa zona (si falta, solo `material`) y `Elemento.materiales` (opcional, como `medidasExtra`) guarda el elegido; `materialDeZona(e, zona)` lo resuelve (el elegido solo vale si la zona lo ofrece: un `cambiarTipo` puede traer uno que el tipo nuevo no admite, y `materialesAdmitidos` lo filtra al editar y al cambiar de tipo). El panel pone un `<select>` «Material de X» junto al color solo en esas zonas; la hoja escribe «Patas (madera)». Lo llevan las patas de mesas, escritorios y sofás (madera, metal, lacado), los tableros y los cuerpos de los muebles de madera o lacado (madera ↔ lacado; los electrodomésticos no), las puertas del esquinero, las estructuras de cama, cuna y litera y los asientos de silla y taburete (madera, lacado, metal). Al cambiar a madera aparece la veta (`texturaDe`); lacado y metal van lisos. La forma es la variante compartida `VARIANTE_PATAS` («Forma de las patas», no «Patas»: la zona de color ya se llama así) y `patas4(…, forma)` hace cilindros; los volúmenes siguen siendo cajas. En el escritorio, la forma no se enseña con dos cajoneras (no quedan patas).
- Texturas (M-12): `editor/vista3d/texturas.ts` genera en el navegador un patrón de luminancia casi blanca por material (`madera`, `tela`, `suelo` —tarima—, `baldosa`, `pared`; el resto liso; el suelo es `baldosa` en baño y cocina y `suelo` en el resto, según `materialDelSuelo` de `nucleo/modelo3d/estancia.ts`) como `DataTexture` de 256 px, compartida, en **lineal** (`NoColorSpace`: en sRGB oscurecería el color elegido) y repetida cada `METROS_POR_MOSAICO`. `materialDe` la pone como `map`, que multiplica el color. Las coordenadas de textura van en metros: `ExtrudeGeometry` y `ShapeGeometry` ya las dan así (prismas, muros, suelo) y cajas y cilindros pasan por `uvsEnMetros` (`geometrias.ts`); una geometría nueva en `Pieza` tiene que hacer lo mismo o la veta se estira con el tamaño. Los patrones son periódicos (sin costura): `texturas.test.ts` lo comprueba. Una caja con `radio` se pinta con `RoundedBoxGeometry` (3 segmentos, también por `uvsEnMetros`); su contorno de selección (`Edges`) se calcula sobre la caja lisa, porque sobre la redondeada saldrían varias líneas por arista.
- Paso estrecho (aviso): hueco de 30 a 59 cm (`HUECO_IGNORADO_CM` y `PASO_MINIMO_CM` en `nucleo/conflictos/constantes.ts`) entre dos muebles con `bloqueaPaso`, o entre uno y una pared, columna o radiador; con menos de 30 no es un paso. Dos tipos del mismo `conjunto` (`'estar'`: sofá, sofá rinconera, sillón y mesa de centro) no se avisan entre sí: se usan juntos y van cerca a propósito. Tampoco avisa un hueco que llena un tercer mueble que toca los dos lados a menos de 30 cm (un módulo de 50 entre otros dos, o entre el frigorífico y la pared): `llenoEntre` y `llenoHastaLaPared` en `detectar.ts`.
- Girar con dos dedos (M-27): en `Lienzo.tsx`, `primerDedoSobre` apunta en la captura (antes de que la pieza lo seleccione) el mueble del primer dedo **solo si ya estaba seleccionado**; con el segundo dedo, si es así y está libre (paso 2, sin medir), `giroConDedos` gira con `moverElemento` de 90° en 90° según el ángulo entre los dedos (grupo `girar:<id>`, se cierra al levantar un dedo); si no, pellizco. Sin la condición de «ya seleccionado», cualquier gesto de dos dedos sobre un mueble giraría (el primer toque lo selecciona).
- Selección múltiple (M-02): `Seleccion` admite `{ tipo: 'elementos', ids }`, siempre con dos o más (`seleccionValida` la reduce a `elemento` o `null` si se borran); es del paso 2. Las acciones de grupo están en `estado/elementos.ts` (`alternarSeleccion`, `seleccionarTodos`, `desplazarSeleccion`, `borrarSeleccion`, `idsSeleccionados`). `pulsarElemento` alterna con Mayús, Ctrl o Cmd, o con `variosActivo` (el modo «Seleccionar varios» del móvil, que se apaga al soltar la selección o cambiar de paso); pulsar un mueble del grupo lo arrastra entero **sin imán** (el imán movería cada uno por su lado), grupo `mover:grupo`. Las flechas mueven el grupo (`teclado:grupo`), Supr lo borra, Ctrl+A selecciona todos en el plano; R y Ctrl+D no hacen nada con un grupo. **Un grupo con un bloqueado no se mueve** (`grupoConBloqueado`: moverse solo los demás deformaría el conjunto) y el panel lo dice. `variosActivo` se apaga solo (suscripción en `crearAlmacen`) en cuanto no queda selección o se pasa a 3D, y su botón es un interruptor (`aria-pressed`) con una nota. Con el teclado: Tab selecciona la pieza enfocada (salvo con un grupo, que no se deshace) y Mayús+Intro alterna sobre la selección de **antes** del foco, así se forma un grupo. El tirador de giro solo sale con un mueble. `e2e/arrastre.spec.ts` arrastra un grupo en Chromium.
- Versión anterior (M-21): `versiones_anteriores` guarda una copia por diseño. `GestionDeDisenos.ActualizarAsync` copia **antes** de `Actualizar` solo si `VersionAnterior.TocaCopiar` (último guardado de hace 30 min o más, o `X-Copia-Previa: 1`, que la web manda en el primer PUT tras «Sobrescribir con la mía»: `Trabajo.copiaPrevia` en `sincronizacion.ts`); la web guarda cada 2 s y copiar siempre no serviría. Una copia pedida (`pedida`: la de sobrescribir y lo que se deja al recuperar) no la sustituye una automática en 7 días; `copiaPrevia` también viaja en la copia local (`decorazon.diseno.<id>`) para sobrevivir a una pestaña cerrada. `POST /disenos/{id}/version-anterior/recuperar` intercambia copia y actual. En la web, «Recuperar la versión anterior» (Más acciones) solo existe en diseños de la cuenta y se desactiva con cambios sin subir. Los tests de la API que dependen del tiempo usan `ApiConRelojAjustable` (`VersionAnteriorTests.cs`), que arranca en la hora real y se reinicia en cada test: los tokens se emiten con ese reloj.
- Carga: las cifras de Lighthouse y el tope están en el índice de mejoras (plan 12, «Medidas de la fase 8»); `web/pruebas-build/presupuesto.test.ts` vigila el tamaño del arranque (JS y CSS que enlaza `index.html`) y del fragmento 3D, y que `index.html` no enlace `Escena3D`. `public/robots.txt` existe a propósito: sin él nginx devuelve `index.html` por el fallback de la SPA. «Cómo funciona» (`/como-funciona`, `paginas/ComoFunciona.tsx`, textos en `textos.comoFunciona`) es la cuarta página indexable (`PAGINAS_INDEXABLES` y `public/sitemap.xml`, que van juntos): sus capturas (`public/capturas/*.webp`, 1000 px de ancho; **ninguna carpeta de `public/` puede llamarse como una ruta**: nginx redirige `/ruta` a `/ruta/` y da 403, lo vigila `seo.test.ts`) son del editor real con los ejemplos y hay que rehacerlas si el editor cambia a la vista; `e2e/como-funciona.spec.ts` comprueba que cargan. La vista previa al compartir la web (`og:image`) es `public/imagen-redes.png`, de 1200 × 630 (la proporción que no recortan WhatsApp, X ni Facebook) y menos de 300 kB (`pruebas-build/seo.test.ts`): sale de `npm run imagen-redes` (Playwright pinta el salón de ejemplo con el nombre y el lema), y hay que rehacerla si cambia `public/ejemplos/salon.png` o el lema. La imagen del primer ejemplo del inicio va `eager` + `fetchpriority="high"` (es el LCP en móvil); un `preload` en `index.html` empeoró el LCP simulado y no se deja.
- Miniaturas 3D del catálogo (M-46, plan 30): una WebP por tipo en `web/public/miniaturas/<id>.webp` (recortada al mueble, dentro de 320 × 112, unos 140 kB las 59) y su manifiesto `src/editor/paneles/miniaturas.generado.ts` (firma del modelo, resumen de los bytes y tamaño por tipo), los dos **generados** con `npm run miniaturas` (determinista: regenerar sin cambios da los mismos bytes; si un tipo falla al pintarse o no responde en 30 s, el script se para con su id). El script arranca Vite en proceso y abre con Chromium (SwiftShader) `web/miniaturas.html`, una página solo de desarrollo (`vite build` construye solo `index.html`; lo vigila `presupuesto.test.ts`) que pinta cada tipo con la `Pieza` de `vista3d`, cámara ortográfica de tres cuartos encuadrada a su caja, sin sombras ni suelo, y lo devuelve por `window.miniaturas`. La URL lleva el resumen de los bytes de la imagen (`?v=`, sha256 recortado), así que una guardada nunca es vieja. La firma (`src/miniaturas/firma.ts`: FNV-1a de las `Pieza3D` por defecto redondeadas a 0,1 mm + `VERSION_DEL_DIBUJO`) sirve para saber que hay que regenerar: `miniaturas.test.ts` falla con el id si un modelo, una variante o un color por defecto cambia sin hacerlo. Cambiar luces, cámara, materiales, texturas o teselación (`vista3d/geometrias.ts`, segmentos de `vista3d/Pieza.tsx`) no cambia ninguna firma: hay que **subir `VERSION_DEL_DIBUJO` a mano** y regenerar. `pruebas-build/miniaturas.test.ts` vigila ficheros, que el resumen sea el de los bytes, tamaños y el tope de peso. La tarjeta pinta un `<img>` decorativo (`alt=""`, `loading="lazy"`, `draggable={false}`; la franja sigue con `pointer-events: none` y los tokens claros de `lienzo.css`, así que de noche también es papel claro) y, si el tipo no está en el manifiesto o la imagen falla, la huella. No se precargan: el service worker las guarda al verlas (`runtimeCaching` `CacheFirst`, caché `miniaturas`; es la única ruta en tiempo de ejecución y `pwa.test.ts` lo comprueba, la API nunca). Las capturas de «Cómo funciona» `amueblar`, `avisos` y `vista-3d` enseñan el catálogo: si las miniaturas cambian a la vista, hay que rehacerlas.
- Teclado en el plano (M-28): con `alPulsar`, `CapaElementos` añade una capa de **asas de foco** (`.capa-elementos__foco`: un `<polygon role="button" tabIndex={0}>` con la caja de cada pieza, sin relleno ni puntero, `aria-label` con nombre, medidas y «bloqueado/a» según el género del tipo, y `aria-current` en la seleccionada), ordenada por posición con las alfombras primero. Recibir el foco selecciona (así Supr, R y las flechas actúan sobre lo que se ve con el foco); Intro y Espacio también; a mitad de un arrastre, nada. **El orden de pintado de las piezas no cambia con la posición** (alfombras debajo, luego inserción): reordenar el DOM durante un arrastre hace que el navegador suelte la captura del puntero y el arrastre se corte (`e2e/arrastre.spec.ts`), y además cambiaría el apilado. El `<svg>` del plano es `role="group"` y los nombres van `aria-hidden`. Sin `alPulsar` (paso 1, midiendo, plano exportado, vista compartida) no hay asas.
- Instalar como app (M-25): `instalacion.ts` guarda el `beforeinstallprompt` (anulado) y `appinstalled`; `conectarInstalacion()` va en `main.tsx` antes de `createRoot` porque el evento puede llegar antes de montar. `useEstadoDeInstalacion()` da `no` (ya en standalone o sin aviso), `aviso` o `ios` (iPhone, o iPad que se presenta como Mac con pantalla táctil); «Instalar Decorazon» en `MenuMas` llama a `instalar()` (consume el aviso: Chrome solo deja enseñarlo una vez) o abre la nota de iOS (`Confirmar` con `soloAceptar`).
- Modo oscuro (M-29): solo `prefers-color-scheme: dark` sobre los tokens de `base.css`, sin selector. Los colores fijos de las hojas son tokens: `--sobre-tinta` (texto sobre fondo tinta), `--primario` + `--sobre-terracota` (botones primarios; de noche la terracota del texto se aclara y la del fondo no), `--bien`, `--peligro-suave`, `--sombra` (`rgb(var(--sombra) / 0.1)`). **El plano no cambia**: `.lienzo` lleva fondo blanco fijo y `.lienzo__svg`, `.panel-catalogo__miniatura`, `.hoja-impresion__pagina`, `.compartido__plano` y `.plano-ampliado__plano` redefinen los tokens claros (`lienzo.css`): todo lo que pinta el plano es papel claro también de noche; la 3D tampoco cambia. Texto sobre `--peligro` va con `--sobre-peligro`. `contraste.test.ts` comprueba los pares WCAG de los dos esquemas (texto 4,5:1, bordes 3:1) sobre `base.css?raw`; `e2e/oscuro.spec.ts` (`colorScheme: dark`) comprueba fondo oscuro, plano claro y consola limpia, y deja capturas en `test-results/`.
- Los tres ejemplos del inicio viven en `web/src/ejemplos/index.ts` como documentos construidos con `documentoNuevo` y `elementoNuevo` (no JSON): `ejemplos.test.ts` comprueba que validan, no tienen conflictos y tienen imagen, y que lo alto y ancho (más de 150 de alto y 60 de ancho) va contra la pared de arriba o la de la derecha: la vista 3D inicial mira desde abajo a la izquierda, y en una de esas esquinas el armario del dormitorio tapaba media habitación. Las imágenes (`web/public/ejemplos/*.png`) se regeneran abriendo una copia del ejemplo y pulsando «Descargar imagen 3D», y se reducen a 1200 × 800 (la captura sale a 2400 × 1600; la primera es el LCP del inicio); después, `npm run imagen-redes`. «Abrir una copia» sigue el flujo de la vista compartida (`sustituiriaDisenoAnonimo` → `Confirmar` → `empezarAnonimoCon`). La guía del primer uso (`editor/GuiaInicial.tsx`) solo sale al crear una estancia anónima con el editor ya montado (suscripción al almacén en `Editor.tsx`) y deja la marca `decorazon.guia = 'vista'` (`editor/marcaDeGuia.ts`); los e2e la llevan puesta de antemano con `storageState` (`e2e/estado-sin-guia.json`, en las dos configuraciones de Playwright) y solo `ejemplos.spec.ts` la quita para probarla.
- En react-three-fiber, si una prop deja de pasarse a un objeto cuyo constructor lleva argumentos (`OrbitControls(object, domElement)`), `diffProps` la pone a **0**, no a su valor por defecto: `rotateSpeed` 0 (no gira), `enableZoom` 0 (el pellizco muere porque los manejadores táctiles comparan por veracidad). Las props que cambian según el modo se pasan siempre, con ternario.
- El build de los e2e es de producción y leería `VITE_ANALITICA_SITIO` de `.env.production`; el tracker falla por CORS desde `localhost` y `vista3d.spec.ts` exige consola limpia. `playwright.config.ts` arranca el `webServer` con esa variable vacía.

## Núcleo TS

Coordenadas con x a la derecha e y hacia abajo, y tolerancia de 0,1 cm. Detalle en `docs/superpowers/plans/2026-10-24-01-nucleo-editor.md`.

Paso del plano a la escena 3D (función única `aEscena`, en `nucleo/modelo3d`): cm a metros, y el eje y del plano pasa a ser el z de la escena (`x_escena = x/100`, `y_escena = z/100` hacia arriba, `z_escena = y/100`). El giro de `θ` grados en el plano es `giroY = −θ·π/180` en la escena.

«Desde dentro» (barra de `Vista3D`) pone la cámara con `camaraDesdeDentro` (1,6 m de altura, 0,6 m dentro desde el centro de la primera puerta, o de la pared 0 sin puerta) y `Escena3D` cambia los `OrbitControls` a distancia fija de un centímetro sin zoom ni desplazamiento (orbitar alrededor de un punto a un centímetro, delante, es girar la cabeza sin andar; con un metro la cámara andaba hasta dos y atravesaba paredes; el sentido por defecto es el natural y un `rotateSpeed` negativo lo invierte); las paredes no se ocultan mientras tanto. Es **un solo** `<OrbitControls>` con todas las props explícitas en los dos modos: React reutiliza la instancia al cambiar de modo y r3f pone a 0 las props que desaparecen de un objeto cuyo constructor lleva argumentos, lo que dejaba la órbita de fuera sin girar. `Captura3D` y `Vista3DSoloVer` no lo usan.

Lo que se pinta en 3D sale de `modelo3d` (`piezasDeElemento`, parametrizado por las variantes) y queda dentro de los `volumenes` del tipo, que son también los que usan los conflictos: lo que se ve es lo que choca. `modelos3dIntegridad.test.ts` lo comprueba para cada tipo con `cajaDePieza` (`nucleo/modelo3d/formas.ts`, la caja envolvente de cualquier forma; también la usa `desplazadasY`), y que el centro de cada pieza caiga en la huella con el mueble girado 37°. Formas de `PiezaLocal` (cm): caja, cilindro vertical, `revolucion` (perfil [radio, z] alrededor de un eje vertical, **antihorario**: sube por fuera y baja por dentro, y para una pared hueca vuelve al primer punto; `lados` 24, con 4 una pirámide con las caras en los ejes y el radio hasta las esquinas; `escalaY` para óvalos), `extrusion` (contorno con `huecos` en `planta` (x, y), `alzado` (x, z) o `perfil` (y, z), de `desde` a `hasta` en el eje que falta; con `radio`, los cantos de las tapas redondeados por el bisel de three, que se extruye con el contorno encogido `contornoEncogido` y lo devuelve a su sitio: sin huecos, como mucho medio grueso y sin que el contorno encogido se dé la vuelta, lo vigila la integridad) y `tubo` (por `puntos` [x, y, z], `codo` redondea las esquinas, `cerrado`; su caja cuenta el disco perpendicular del extremo, así una pata vertical no baja del suelo). Ayudas `revolucion`, `extrusion` (huecos y radio como opciones), `tubo`, `brazoEnrollado` (brazo de sofá con la parte de arriba en semicírculo: alzado o perfil según su lado largo; sofá, sillón, sofá cama y rinconera), `marco` (extrusión de alzado con el hueco de la lámina: cuadro y espejo) y `ovalo` (una extrusión en planta con los extremos en semicírculo) en `modelos.ts`, y contornos y perfiles (`elipse`, `rectanguloRedondeado`, `elipsoide`, `onda`) en `catalogo/perfiles.ts`. Lo que ya las usa (plan 29): lámpara, planta (matas de elipsoides de 12 lados, `LADOS_MATA`), taburete (aro de tubo o listones según las patas), silla (faldones y respaldo curvado 4,5 cm: el volumen del respaldo tiene **6** de fondo y los montantes siguen a las patas de atrás por delante), papelera y puf (revolución, ovalada con `escalaY`), mesa auxiliar redonda (pie de revolución), bañera (paredes de una pieza con la cubeta redondeada, fondo oscuro y respaldo inclinado de alzado), campana (en isla, pirámide de revolución de 4 lados; en pared, cuña de perfil, porque una revolución centrada dejaría hueco contra la pared), perchero (ganchos de tubo), mesa plegable (escuadra de perfil con hueco), silla de oficina (base de brazos de tubo con ruedas, respaldo curvo), grifos de fregadero y bañera (caño de tubo), tiradores (`tiradorDeBarra`: tubo en C de radio 0,5 sin codos, en la misma franja que la tableta de antes; los usan `tiradores` y `cajonesApiladosEn`, el armario esquinero lleva los suyos), inodoro y bidé (`tazaDeLoza`: revolución ovalada hueca con agua; su cuerpo trasero queda por debajo del fondo de la cubeta o asomaría dentro), lavabo (encimera con huecos `elipse`, seno de revolución debajo; el cuerpo macizo del mueble acaba bajo el seno y encima solo van costados y trasera, porque su tapa taparía el seno) y cortina (paños `onda` y barra de tubo). Las tres nuevas viajan a `Pieza3D` en metros en el sistema del mueble con `origen` + `giroY` (la malla se coloca entera; `geometrias.ts` pasa los ejes del plano a los de la escena sin espejos: un espejo da la vuelta a las caras). Sus normales salen de `toCreasedNormals` a 35° calculado **en cm** (une vértices a 1/100 de unidad: en metros juntaría las dos caras de una pantalla de 5 mm), sus uv van en metros y su contorno de selección usa `threshold` 35 (sin una línea por faceta). La extrusión en planta gira +π/2 en X y no cambia el signo de y como `geometriaPrisma`: con huecos, `ExtrudeGeometry` triangula mal el contorno al revés. `geometriasFormas.test.ts` comprueba cada geometría por su volumen con signo (caras hacia fuera) y su caja frente a `cajaDePieza`. Una caja admite `radio?` (como mucho medio lado menor, lo vigila la integridad) y sale redondeada: lo llevan el tapizado (`asientoTapizado` y la rinconera: `RADIO_ESTRUCTURA` 2, también el de los cantos de los brazos enrollados, y `RADIO_COJIN` 5 en `modelos.ts`), la ropa de cama y los tableros y asientos de madera (1). Los cojines largos se parten con `cojinesEnTramo` (70 cm como mucho). En 3D se selecciona, edita, borra y se **mueve** el mueble ya seleccionado arrastrándolo por el suelo (M-10, `vista3d/arrastre3d.ts`: `puntoDelSuelo` proyecta el rayo en y = 0, `moverEn3D` con el mismo imán, grupo `mover:<id>`; `Mueble3D` captura el puntero y apaga `controls.enabled` mientras dura). Girar sigue solo en 2D, y un mueble sin seleccionar no se arrastra: empezar sobre él gira la cámara.

## Despliegue

Con `srv` (skill `servidor`), desde la raíz del repo: `srv.json` publica la web estática (`deploy/construir-web.mjs` la compila a partir del commit) en `decorazon.angelgf.com.es` y la API en `decorazon-api.angelgf.com.es` (salud `/salud`, `tamanoMaximo: "2m"` porque un diseño puede pesar 1 MB), con la base `decorazon`.

- Publicar: `srv subir` (ensayo) y `srv subir --publicar`; volver atrás: `srv volver`; logs: `srv logs api`; estado: `srv estado`.
- Las migraciones las aplica `srv subir` con el bundle de EF; fuera de Development la API no migra sola.
- Secretos (los pone Angel con `srv secreto <NOMBRE>`; ver solo nombres con `srv secreto --nombres`): `ConnectionStrings__Decorazon`, `Jwt__ClaveDeFirma` y `Correo__ClaveDeApi`. El resto de la configuración de producción está en `appsettings.json`.
- La web de producción llama a la API de `web/.env.production` (`VITE_API_URL`) y carga la analítica si hay `VITE_ANALITICA_SITIO`.
- nginx (plantilla de srv) sirve la web con `Cache-Control: no-cache, no-transform`: el service worker y el manifiesto se revalidan siempre.
- Tras un despliegue, una pestaña con la versión anterior recarga una vez si no encuentra un fragmento (`web/src/recargaPorVersion.ts`).
